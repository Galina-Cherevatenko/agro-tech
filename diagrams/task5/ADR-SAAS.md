# ADR-005: Мультитенантная SaaS-платформа

### Название задачи:
Проектирование мультитенантной SaaS-платформы на основе Edge-first архитектуры

### Автор:
Череватенко Галина

### Дата:
2026-04-30

### Статус:
Предложено (Proposed)

---

## Контекст

MVP успешно работает на собственных фермах компании. Компания планирует вывести решение на рынок как коммерческую SaaS-платформу для агрохолдингов.

**Ссылка на основной вариант:**  [`../task4/ADR.md`](../task4/ADR.md)

### Бизнес-цели

1. Создать новый источник регулярного дохода
2. Уменьшить TCO для клиентов за счёт облачной модели
3. Ускорить выход на рынок и масштабирование
4. Собрать данные для создания собственных ML-моделей

### Требования к SaaS-платформе

| № | Требование |
|---|------------|
| S-1 | Обеспечивать полную изоляцию данных между клиентами |
| S-2 | Поддерживать гибкую систему подписок с разными тарифными планами |
| S-3 | Предоставлять API для интеграции с системами клиентов |
| S-4 | Иметь панель самообслуживания для управления аккаунтом |
| S-5 | Масштабироваться горизонтально по мере роста числа клиентов |
| S-6 | Собирать метрики использования для аналитики и биллинга |
| S-7 | Интегрироваться с российскими платёжными системами (ЮKassa, СБП) |
| S-8 | Предоставлять документацию и API для самостоятельной интеграции |

## Задача 1. Проектирование мультитенантной архитектуры

### Варианты изоляции данных

1. **Вариант А: Schema per Tenant** – единая БД, отдельные схемы для каждого клиента.
2. **Вариант Б: Database per Tenant** – единый кластер БД, отдельная база данных для каждого клиента.
3. **Вариант В: Instance per Tenant** – выделенные инстансы БД (и часто микросервисов) для каждого клиента.

### Сравнение вариантов по критериям

| Критерий | Schema per Tenant | Database per Tenant | Instance per Tenant |
|----------|-------------------|---------------------|---------------------|
| Уровень изоляции данных | Низкий/Средний | Высокий | Максимальный |
| Стоимость инфраструктуры | Низкая | Средняя | Высокая |
| Сложность миграции данных | Низкая | Средняя | Высокая |
| Масштабируемость (число тенантов) | Ограничена лимитами БД | Высокая | Ограничена ресурсами кластера |
| Производительность запросов | Возможны contention-эффекты | Стабильная | Максимальная |
| Соответствие ФЗ-152 / Compliance | Требует доп. шифрования | Удовлетворяет базовым требованиям | Полное соответствие |

### Выбранный вариант
На основе критериев из Задания 4 (баланс стоимости, изоляции и масштабируемости) выбран **Вариант Б: Database per Tenant**. Он обеспечивает достаточную изоляцию для коммерческих клиентов, упрощает бэкапы/миграции на уровне тенанта и соответствует требованиям российского законодательства при корректной настройке шифрования.

## Задача 2. Разработка системы биллинга и монетизации

### Компоненты системы
- **Subscription Manager** – управление тарифами, пробными периодами, апгрейдами/даунгрейдами.
- **Usage Metering** – сбор метрик потребления (количество устройств, объём данных, API-вызовы).
- **Invoice Generator** – формирование счетов и актов в соответствии с 54-ФЗ.
- **Payment Gateway Adapter** – унифицированный интерфейс для подключения платёжных провайдеров.

### Интеграция с российскими платёжными системами
- Поддержка **ЮKassa** и **СБП** через единый адаптер.
- Импотентные операции, обработка вебхуков о статусе платежа, автоматические retry-политики.
- Хранение токенов оплаты в зашифрованном виде, соответствие требованиям ЦБ РФ.
- Вебхуки и email-уведомления о списаниях и обновлениях подписки.

## Задача 3. Интеграции с клиентами

### API для клиентов SaaS-платформы

| Тип API | Протокол | Назначение |
|---------|----------|------------|
| **REST API** | HTTPS + OpenAPI | Управление, получение метрик, конфигурация |
| **Webhooks** | HTTP POST + retry | Оповещения о событиях (alert.triggered, device.offline) |
| **Kafka Streams** | Kafka Protocol | Real-time поток событий |
| **S3 Export** | S3 API | Выгрузка больших объёмов данных |

### Scope доступного функционала

| Категория | Доступно в API | Примечание |
|-----------|---------------|-------------|
| **Метрики** (поголовье, расход кормов, качество воды) | ✅ | READ-ONLY |
| **Оповещения** (получение, история) | ✅ | READ-ONLY |
| **Управление устройствами** (камеры, кормушки) | ✅ | READ + WRITE (Business/Enterprise) |
| **Настройка правил** (пороги, алерты) | ✅ | READ + WRITE (Business/Enterprise) |
| **Управление пользователями** (роли, доступ) | ✅ | READ + WRITE (только админ) |
| **ML-модели** (загрузка своих) | ❌ | Только через поддержку (Enterprise) |

### Dev Portal

| Компонент | Технология | Назначение |
|-----------|------------|------------|
| **Документация API** | OpenAPI 3.0 + Swagger UI | Интерактивная документация |
| **API Playground** | React + Swagger UI | Тестирование запросов в браузере |
| **API Key Management** | Self-service portal | Создание и ротация ключей |
| **Webhook Tester** | Встроенный инструмент | Тестирование webhook-эндпоинтов |
| **Status Page** | Public dashboard | Статус платформы в реальном времени |
| **SDK** | Python, Node.js, Go | Библиотеки для быстрой интеграции |

### Диаграмма примера интеграции с клиентом

- [C2: Интеграция с клиентом](diagrams/integration/c2-integration-example.puml)

**Сценарии интеграции для клиента:**

| Сценарий | Направление | Технология |
|----------|-------------|------------|
| **Телеметрия с ферм** | Edge Agent → Платформа | gRPC (batch 10 мин) |
| **Оповещения о событиях** | Платформа → ERP клиента | Webhook → Kafka |
| **Получение метрик** | Платформа → Power BI клиента | ODBC / JDBC |
| **Управление (опционально)** | ERP клиента → Платформа | REST API |

## Результаты

### Выполненные требования

| № | Требование | Реализовано |
|---|------------|-------------|
| S-1 | Изоляция данных | ✅ Database per Tenant |
| S-2 | Гибкая система подписок | ✅ Starter / Business / Enterprise |
| S-3 | API для интеграции | ✅ REST, Webhooks, Kafka, S3 |
| S-4 | Self-Service Portal | ✅ Регистрация, API keys, биллинг |
| S-5 | Горизонтальное масштабирование | ✅ K8s, шардирование БД |
| S-6 | Сбор метрик использования | ✅ Usage Collector + Prometheus |
| S-7 | Платёжные системы (РФ) | ✅ ЮKassa, СБП, CloudPayments |
| S-8 | Документация для интеграции | ✅ Dev Portal + OpenAPI + SDK |

### Бизнес-цели

| Цель | Как достигается |
|------|-----------------|
| Новый источник дохода | Подписки Starter/Business/Enterprise |
| Снижение TCO для клиентов | Облачная модель, не нужно покупать и поддерживать свою инфраструктуру |
| Ускорение масштабирования | Self-Service онбординг, автоматический провиженинг |
| Сбор данных для ML | Агрегированные анонимизированные данные с ферм |
