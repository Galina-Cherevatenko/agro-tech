### Название задачи:
Детализация компонентной архитектуры (C3-C4) для двух вариантов решений

Череватенко Галина

### Дата:

### Контекст
Необходимо сравнить два архитектурных подхода на уровне компонентов и кода, чтобы команда разработки могла выбрать и реализовать.

### Сравнение компонентов

| Компонент | Основное решение (Edge-first) | Альтернативное решение (Cloud-Edge Hybrid) |
|-----------|-------------------------------|---------------------------------------------|
| **Видеоаналитика** | YOLOv8 + DeepSORT на edge GPU | MobileNet на edge + YOLOv8 в облаке |
| **Детекция драк** | На edge (<5 сек) | В облаке (задержка от 2-10 сек) |
| **Детекция задавливания** | На edge (мгновенно) | В облаке (задержка) |
| **Офлайн-алерты** | Полные (WebSocket) | Базовые (по Motion detection) |
| **Управление кормушками** | Прямое (через MQTT) | Прямое + кэш команд |
| **Синхронизация** | Batch 10 мин | Стриминг + Batch как fallback |
| **Локальное хранилище** | TimescaleDB (30 дней) | SQLite (7 дней) |
| **Edge HW** | GPU-сервер ($2000+) | CPU (Raspberry Pi 4, $100) |
| **Облачные затраты** | Низкие (только метаданные) | Высокие (видео трафик + GPU) |

### Компромиссы по вариантам

**Основное решение:**
- Высокий CAPEX, низкий OPEX
- Полная автономность
- Быстрое оповещение
- Сложнее обновлять модели

**Альтернативное решение:**
- Низкий CAPEX, высокий OPEX
- Зависимость от интернета
- Задержка оповещения выше
- Мгновенные обновления моделей

### Рекомендация

Для **MVP с несколькими фермами** — Основное решение (Edge-first), так как офлайн-режим и скорость оповещения — критические требования.

Альтернативное решение — для ферм со стабильным интернетом или для 2-го этапа проекта (дешёвые фермы со слабой ИТ-инфраструктурой).
