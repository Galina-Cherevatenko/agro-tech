### Нефункциональные требования

| № | Требование |
|---|---|
| NFR-1 | **Отказоустойчивость:** 99,95% доступности |
| NFR-2 | **Производительность (оповещение):** Не более 5 секунд от момента детекции до отправки уведомления |
| NFR-3 | **Производительность (видеоаналитика):** Реакция в реальном времени (миллисекунды на детекцию) |
| NFR-4 | **Автономность:** Полная работа при отсутствии интернета, синхронизация с задержкой до 10 минут после восстановления связи |
| NFR-5 | **Расширяемость:** Возможность добавления нового функционала без изменения существующего |
| NFR-6 | **Масштабируемость:** Поддержка неограниченного количества ферм (агентов) |
| NFR-7 | **Безопасность:** Разделение ролей, современные методы аутентификации |
| NFR-8 | **Совместимость с оборудованием:** Поддержка разных производителей камер, кормушек, поилок |
| NFR-9 | **Сетевые ограничения:** Работа поверх нестабильного WiFi, экономия трафика |
| NFR-10 | **Освещение:** Видеоаналитика должна работать в ночное время |

### Решение

#### Диаграмма контекста (C1) - Основное решение

> 📄 **Файл диаграммы:** [`../task1/context-diagram-primary.puml`](../task1/context-diagram-primary.puml)

*Диаграмма показывает:*
- Персоны: оператор фермы, центральный оператор, ветеринар, системный администратор, директор
- Внешние системы: IP-камеры, кормушки/поилки, датчики фильтрации воды
- Существующую платформу: Kafka, ClickHouse, Power BI, 1С:Агро
- Новые компоненты: Edge-агент (GPU), центральная платформа (K8s), мобильное приложение, веб-панель
- Ключевые связи: офлайн-алерты через WebSocket, синхронизация batch 10 минут

#### Логика принятия решений и выбора технологий

| Требование | Принятое решение | Обоснование |
|------------|------------------|-------------|
| **Автономность (NFR-4)** | Edge-агент на каждой ферме с локальной БД | Работа без интернета — критическое требование |
| **Оповещение < 5 сек (NFR-2)** | Видеоаналитика на GPU прямо на ферме | Передача видео в облако добавит 2-5 сек только на сеть |
| **Совместимость с оборудованием (NFR-8)** | IoT Gateway на Node-RED + адаптеры | Поддержка Modbus, OPC-UA, MQTT |
| **Синхронизация до 10 мин (NFR-4)** | Batch-передача данных раз в 10 минут | Экономия трафика, снижение требований к каналу |
| **Отказоустойчивость (NFR-1)** | Активный-пассивный кластер на ферме + K8s в центре | 99.95% при разумных затратах |
| **Масштабируемость (NFR-6)** | Горизонтальное масштабирование центра через K8s | Неограниченное количество ферм |
| **Видеоаналитика** | YOLOv8 + DeepSORT на GPU | Лучшее соотношение скорость/точность |

#### Описание компонентов решения

**Edge-агент (на каждой ферме):**
- Запуск моделей видеоаналитики от партнёров на GPU
- Управление оборудованием через адаптеры под разных производителей
- Локальное хранение данных (работа при обрыве интернета)
- WebSocket-сервер для оповещения оператора
- Синхронизация с центром раз в 10 минут

**Центральная платформа:**
- Агрегация данных со всех ферм
- Управление конфигурациями и правилами детекции
- Предоставление API для веб- и мобильного приложений
- Формирование метрик для внешних систем

### Альтернативы

#### Диаграмма контекста - Альтернативное решение (Cloud-Edge Hybrid)

> 📄 **Файл диаграммы:** [`../task1/context-diagram-alternative.puml`](../task1/context-diagram-alternative.puml)

*Диаграмма показывает альтернативный подход с тонким edge-агентом (CPU only), локальным буфером и облачной видеоаналитикой (Serverless GPU).*

#### Сравнение альтернатив

| Критерий | Основное решение (Edge-first) | Альтернативное решение (Cloud-Edge Hybrid) |
|----------|-------------------------------|---------------------------------------------|
| Edge-оборудование | GPU-сервер ($2000+) | CPU (Raspberry Pi, $100) |
| CAPEX | Высокий | Низкий |
| OPEX | Низкий | Высокий (трафик + cloud GPU) |
| Видеоаналитика без интернета | ✅ Полная работа | ❌ Только базовая |
| Оповещение < 5 сек | ✅ Да | ❌ Только базовое |

**Почему выбрано основное решение:** Ключевые требования NFR-4 (автономность) и NFR-2 (оповещение <5 сек) делают альтернативу неприемлемой.

### Недостатки, ограничения, риски

#### Недостатки

1. **Высокий CAPEX** — GPU-серверы для каждой фермы (от $2000)
2. **Сложность обновлений** — модели ИИ нужно обновлять на каждом edge-агенте
3. **Дублирование логики** — часть правил на edge, часть в центре
4. **Квалификация персонала** — нужны специалисты для поддержки edge

#### Ограничения

1. **Задержка синхронизации** — при обрыве интернета >10 минут центр не получает свежие данные
2. **Чувствительность видеоаналитики** — ложные срабатывания от теней/освещения (допустимо для MVP)
3. **Поддержка камер** — только RTSP/H.264

#### Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Нестабильный WiFi | Высокая | Высокое | Проводное подключение, резервирование |
| Выход из строя edge-сервера | Средняя | Критическое | Активный-пассивный кластер |
| Модель ИИ путает тени/свет | Высокая | Среднее | Постобработка, трекинг |
| Рост ферм → перегрузка центра | Средняя | Высокое | Горизонтальное масштабирование |

#### Компромиссы

| Компромисс | Решение | Обоснование |
|------------|---------|-------------|
| CAPEX vs OPEX | Высокий CAPEX, низкий OPEX | Окупается за счёт отсутствия облачных расходов |
| Автономность vs централизация | Приоритет автономности | Работа без интернета — критическое требование |
| Скорость vs точность | Скорость детекции (<5 сек) | Для оповещения о драках скорость важнее |
